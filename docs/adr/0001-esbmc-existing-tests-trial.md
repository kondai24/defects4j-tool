# ADR 0001: ESBMC と既存テストによる自動検査（不採用）

- 状態: 不採用（[ADR 0002](0002-jbmc-verify-step.md) で置き換え）
- 日付: 2026-10-31

## 背景

LLM による修正の評価は `defects4j test` の合否だけで行っていた。テストに通っても実は誤っている修正（過学習パッチ）を見つけるため、モデル検査器でプログラムを検査できるかを試した。

試行の対象は Defects4J の Math-94 で、バグ版（94b）と修正版（94f）の両方を使った。LLM による修正の生成は行っていない。検査の流れが成り立つかだけを確認した。

## 検討した方式

バグごとに人が入力や期待値を用意しない。既存テストに書かれた呼び出し・入力・期待値をそのまま使って ESBMC で検査する。

1. バグ版と修正版をそれぞれ checkout してビルドする。
2. `defects4j export -p tests.relevant` で関連テストクラスを取得する。
3. 関連テストをまとめて呼び出す入口（`Main`）を自動生成する。JUnit3 の仕組みを使う。
4. 生成した入口を JVM で実行する。実行したテストの一覧、失敗件数、失敗したテスト名が `defects4j test -r` と一致するかを確かめる。
5. Soot でプロジェクトのクラス、テストクラス、依存ライブラリを Jimple に変換する。
6. jimple2json で JSON に変換する。すべて変換できた場合だけ ESBMC で検査する。

## 結果

| 確認項目 | バグ版 94b | 修正版 94f |
| --- | ---: | ---: |
| 実行したテスト数 | 547 | 547 |
| 失敗したテスト数 | 1 | 0 |
| 標準の Defects4J 実行との照合 | 一致 | 一致 |
| Soot が出力したクラス数 | 948 | 948 |
| JSON 変換に失敗したクラス数 | 735 | 735 |
| 対象プログラムの ESBMC 検査 | 未到達 | 未到達 |

- テストの選択と実行を機械的に行う部分は成り立った。
- JSON 変換は 948 クラス中 735 クラスで失敗した。小数の表記や interface などの構文に対応していなかったためである。
- ESBMC の Java 入力を単純なプログラムで試したところ、`Unexpected expr type: instanceof` などで止まった。
- ESBMC 8.6 の Java 入力は、`long` と `double` を int として扱う。文字列、標準ライブラリ、例外の型にもほとんど対応していない。
- 同じ Math-94 を JBMC で補助的に検査したところ、既存テストの入口をそのまま使ったため 60 秒で時間切れになった。

## 決定

ESBMC と既存テストの入力による検査は採用しない。

- **ESBMC を使わない理由**: Java の型やライブラリへの対応が狭く、実験対象の 103 件の多くを扱えない。
- **既存テストの入力で検査しない理由**: 検査に使う入力がテストと同じなので、得られる結果もテストと同じになる。過学習パッチを見つけるための新しい情報が得られない。

試行のためのスクリプト（`workspace/esbmc_*`、`workspace/jbmc_existing_tests_trial.py`、`workspace/esbmc_support/`）と、その説明（`docs/esbmc-*.md`）は ADR 0002 の実装の際に削除した。

## 結果として残ったこと

- 「テストに通った修正が正解版と同じように動くか」を、テストにない**任意の入力**で確かめる必要がある。
- そのためには Java の意味（`long`/`double`、文字列、例外）をそのまま扱える検査器が必要である。この 2 点が ADR 0002 の出発点になった。
